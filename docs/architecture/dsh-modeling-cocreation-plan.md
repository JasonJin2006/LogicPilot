# DSH 上的 LogicPilot 人机共创建模平台：实施总计划

日期：2026-09-21  
状态：**待实施设计；不是完成报告**。此前 `integrations/dsh-des` 是被用户否定为主架构的探索原型。  
首个验收场景：小型仓储／产线中的搬运与任务分配。  
最终产品入口：用户从空项目开始，用自然语言描述所需系统，与 AI 一起生成、检查、修改、运行并改进模型。  
执行顺序见 [逐任务执行单](../maintenance/dsh-coCreation-tasks.md)，交接提示词见 [执行提示词](../maintenance/dsh-coCreation-handoff.md)。

## 0. 接手者先读：不可改变的产品意图

1. DSH 是应用宿主。复用其聊天、会话、工作区、右侧面板、分屏、全屏、设置、工具、插件生命周期和凭据机制。默认不改 DSH 源码。
2. LogicPilot 是进入 DSH 插件体系的建模、仿真、决策与实验能力。不能另建一套主客户端后嵌进面板，也不能仅包装一个独立 Web 应用。
3. 流程图、3D、参数表、实验结果属于可编辑的领域文档及其视图。它们承担人机共创，不只是播放动画。人、AI 和批量实验访问同一模型版本与业务服务。
4. 仓储是首个场景包和验收用例，不是平台的唯一数据类型。平台核心中禁止依靠 `if warehouse` 等场景分支组织通用业务。
5. “从零”指从空项目和需求开始组合已有能力、建立新模型。首版不承诺自动生成任意物理引擎、可信插件或训练数据；遇到未支持能力必须说明缺口。
6. 复用 LogicPilot 的 Artifact Graph、事务、DSL/IR、ExecutionService、原生运行时与现有空间能力。缺什么补什么，不把已有体系绕开重写为浏览器玩具引擎。
7. 通用 LLM、Jev 类决策模型、专用预测／控制模型、确定性代码承担不同工作；它们均不是整个系统的唯一真相来源。
8. 本次用户请求是详细计划。本文件创建不代表已经授权发布服务、购买额度或覆盖其他开发者工作；后续用户要求实施时按具体任务执行。

### 0.1 执行纪律

- 每次开始先读根 `AGENTS.md`，检查 `git status --short` 和涉及文件的当前内容。当前工作树含大量用户未提交改动，不得 reset、恢复旧提交、全量格式化或无差别暂存。
- 当前源码和可复现测试优先于历史文档及聊天中的“已完成”。尤其不能把旧测试通过数字引用为本轮证据。
- 只完成执行单中的一个有界任务后更新证据。接口声明、假数据、截图、能启动，都不等于完成业务闭环。
- 不扩大到另一个 Agent Harness、插件市场、云集群或多人实时协同编辑。允许多个本地会话研究一个项目；这不等于实现多人协同产品。
- 不自动修改全局 DSH 环境来解决包缺失。先核对宿主版本和包解析来源；所有安装、构建和启动步骤必须可复现。

## 1. 最终用户旅程

### 1.1 空项目输入

用户说：

> 我需要一个 30×20 米的小仓库。左侧入库，右侧出库，中间四组货架；两辆搬运车服务两个拣选工位。订单有普通和加急两种，我想知道什么时候会拥堵、怎样分配任务更好。

系统应完成：

1. 识别目标、系统边界、参与对象、流程、空间、实验问题和已给约束。
2. 建立需求草案；提取用户给定事实。缺失参数记录为“待确认”或“暂定假设”，给出单位与影响。
3. 只询问会改变模型结构、约束或结论的关键问题。可逆布局和初始参数可以先给可修改草案，不用每个参数都打断用户。
4. 查询已安装能力，选择领域包、范式、运行时与视图。不能先编造模型类型，最后才发现运行时不支持。
5. 生成语义模型、空间布局、行为策略、初始实验；这些产物之间建立显式版本引用。
6. 自动校验：引用、单位、资源、流程连通性、空间可达性、运行时支持、决策动作合法性。
7. 在 DSH 右侧打开模型文档。用户看到流程与占位 3D，以及尺寸假设、诊断和实验目标。
8. 用户选择、拖动、修改参数；或对选中对象说“把它放到右侧，留两米通道”。AI 接收结构化选择上下文，提出局部变更。
9. 变更通过同一事务提交；图、3D 和参数同步。运行中的实验仍固定在原版本，新编辑不会悄悄改变它。
10. 创建运行；显示实体移动、资源占用、队列、决策记录及真实指标。失败、超时、缺模型提供方必须可诊断。
11. 用户与 AI 比较方案，例如 FIFO、最近空闲车、加急优先、Jev 判断策略。结论引用实际运行证据与未确认假设。
12. 用户保留一个方案，继续讨论；关闭 DSH 后重新打开项目，模型、变更记录和已完成结果仍在。

### 1.2 人机共创的最低标准

- “这个工位”可解析到当前视图中的稳定对象 ID；多个候选时展示候选或询问，而不猜错对象。
- AI 改动前后差异可见；用户能修正、接受或撤销。已明确授权的批量修改可以直接提交，但仍需保留差异和撤销记录。
- 人拖动对象与 AI 更新对象，走同一语义命令和版本校验。
- 选择对象不改变模型版本；纯视口缩放不改变仿真输入；实体物理位置改变会产生语义／空间版本变更。
- AI 不能通过替换整个 JSON 消除用户刚做的其他修改。首版正式工具使用有类型的局部操作和基础版本。
- 参数估计是估计，几何占位是占位，模型运行成功不是现实系统已验证。

## 3. 目标架构与包边界

```text
DSH：聊天 / 工作区 / 会话 / 凭据 / 工具 / 事件 / 右侧面板
  │
  ├─ LogicPilot 协作插件：需求、选择上下文、工具、变更预览、诊断说明
  ├─ LogicPilot 项目模型服务：artifact、revision、语义命令、约束
  ├─ LogicPilot 能力与领域包：构件定义、默认值、知识、lowering
  ├─ LogicPilot 运行与实验服务：已有 ExecutionService + native providers
  ├─ LogicPilot 决策服务：候选动作、提供方、预算、结果、重放
  └─ LogicPilot 文档视图：流程 / 3D / 参数 / 实验 / 决策检查
          所有视图均读取同一模型与运行记录，不持有另一份业务真相
```

### 3.1 推荐目录（目标，尚未创建的文件不要当作已有能力）

```text

    bundle/                # profile 组合、版本范围与安装检查
    project/               # Cordis 项目/模型服务适配、工作区映射
    modeling/              # Agent 上下文、工具、需求生成、修复编排
    execution/             # 既有运行服务的 Cordis/Remote 适配
    decisions/             # 决策服务及规则提供方

    workbench/             # DSH 原生 tab/slots，2D/3D/实验视图
  tests/                   # 宿主装载、跨插件、浏览器、安装回归
```

| 服务 | 唯一职责 | 禁止持有 |
|---|---|---|
| `logicpilotProjects` | DSH workspace → project；打开/创建/枚举 artifact | 当前聊天窗口的唯一全局模型 |
| `logicpilotModels` | 读取、提案、校验、提交、撤销和版本关系 | 仿真时钟、Three.js 对象 |

| `logicpilotDecisions` | 决策请求与提供方、动作合法性、记录、重放 | 直接修改物理世界的权限 |

### 3.3 安装与版本规则

- 初始支持本机已验证的 DSH `0.1.6-alpha.2`；执行时核实实际版本。后续升级需要兼容性回归，不能自动跟随 `latest` 后仍称同一基线。
- Cordis/DSH 身份敏感组件使用匹配的 peerDependencies，由宿主供给。禁止把旧 `dsh-llm`/`dsh-tools` 安装进 profile 覆盖宿主。
- 安装检查输出包名、版本、解析来源，发现不兼容时在激活前失败，给出修复指引。不得静默降级为假提供方。
- Three.js 等浏览器私有实现可以随包构建；React 与宿主框架共享身份。客户端按 DSH 支持的打包协议构建，不依赖开发机器绝对路径或扫描 pnpm 内部目录。
- 先用专用测试 profile；正式 profile 安装保留所有已有用户插件/patch。禁止重写整个 profile 以只保留 LogicPilot。
- 独立离线启动可用：没有 Jev 凭据时规则基线仍可运行，Jev 明确 unavailable。

## 4. 领域对象与契约

### 4.1 身份与权威关系

```text
Project
 ├─ RequirementsBrief → Assumptions
 ├─ SystemModel revision
 │   ├─ SemanticGraph（实体/流程/资源/关系）
 │   ├─ SpatialModel（物理空间/通道/路径/碰撞体）
 │   ├─ BehaviorBindings（决策位置与提供方绑定）
 │   └─ ViewPresentation（二维布局/可视资产引用）
 ├─ ChangeProposal → validated changes → committed revision
 ├─ ExperimentSpec → Run → Replications → Evidence / Trace
 └─ DatasetManifest → TrainingSpec → ModelArtifact → Evaluation

DSH SessionBinding → 当前 project/artifact/view/selection/run
```

不是要求把所有内容存进一个 JSON。所有内容属于同一版本化 artifact 图，通过引用闭包得到一致快照。高频 trace 单独存文件和索引，Artifact Graph 只保存引用、digest、版本及摘要。

### 4.2 必须有的字段

| 对象 | 最低字段与约束 |
|---|---|
| Project | `projectId`、schemaVersion、工作区映射、根 artifactRefs、所需 capability/版本、创建来源 |
| RequirementsBrief | 目标、边界、实体、流程、空间、约束、实验问题、用户给定值、缺失信息、接受条件 |
| Assumption | `id`、对象/参数引用、值与单位、来源(user/document/default/inferred)、状态(provisional/confirmed/rejected)、理由、影响 |
| SystemModel | 稳定 objectId、类型/capabilityId、语义参数、带类型关系、空间/策略/表示引用；不出现只为特定 demo 服务的固定 ID |
| ChangeProposal | proposalId、actor、projectId、baseRevision、操作列表、来源意图、受影响对象、诊断、状态、幂等键 |
| SessionBinding | sessionId、projectId、artifactId、viewId、selectionIds、可选 runId；绑定只引用对象，不拥有模型 |
| ExperimentSpec | model revision closure、runtime/version、初始条件、horizon、warmup、replications、seed plan、策略绑定、预算、指标定义 |
| DecisionRequest | requestId、runId、replicationId、simTime、decisionPointId、actorId、observation、候选动作、硬约束结果、提供方配置版本、deadlineMode |
| DecisionRecord | 请求引用、输入 digest、实际模型/提供方版本、输出、概率/置信度(若有)、耗时、成本、fallback/拒绝理由、最终被应用动作 |
| ModelArtifact | 任务、输入/输出 schema、训练数据 digest、代码/模型版本、指标、适用范围、文件 digest；不是无来源权重文件 |

这些字段需要复用已有 Artifact/Execution 契约后增量定义。不要复制一套只改名字的 Revision/ExecutionSession。

### 4.3 坐标与空间语义

- 对外统一 SI 单位：米、秒、kg（若使用）。数值与单位一起经过校验，不用字符串单位参与运行计算。
- 文档空间：右手系，X/Z 地面、Y 向上；位置取物体底面中心；尺寸为宽/高/深；朝向为绕 Y 轴角度，契约明确度或弧度。
- 原生空间图若使用 X/Y 地面，专门适配器映射：文档 `(x,z)` → 内核 `(x,y)`，高度另传。用非对称 L 形路径测试，不仅测原点或直线。
- 2D 流程节点位置只控制文档排版；3D 物理位置影响空间模型。不能拖动流程图就改变搬运距离。
- 视觉 mesh、物理占用 footprint/collision proxy、导航节点分别建模并绑定稳定对象 ID。替换视觉资产不能偷偷改变设备容量或导航。
- `distance/speed`、固定运输时延、经验预测时延是不同运输模型，必须显式选择，不能叠加计算或暗中互换。

## 5. 从自然语言到可执行系统

### 5.1 生成状态机

`empty → interpreting → brief-draft → composing → validating → reviewable → executable → experimenting → refining`

每步失败返回带对象和建议的诊断；在当前草案上修复。中途取消保存草案，不留下半提交项目。

| 阶段 | 输入 | 输出 | 必须验证 |
|---|---|---|---|
| 理解需求 | 当前用户请求、已授权文档、已有项目上下文 | RequirementsBrief | 区分明确要求和模型推断；不擅自改变目标 |
| 能力选择 | brief、当前 capability registry | CompositionPlan | 每项所需能力都有兼容提供方；标记缺口 |
| 语义建模 | plan、构件定义、领域知识 | typed operations | 对象存在、端口/关系类型正确、资源完整 |
| 空间构建 | 对象尺寸、边界、通道约束 | SpatialModel + 诊断 | 场地内、无非法穿插、路径可达、通道宽度 |
| 行为与实验 | 决策点、目标、预算、参数来源 | BehaviorBindings/ExperimentSpec | 动作可执行；provider 可用；运行时支持 |
| 变更预览 | base revision + operations | 可审阅差异与假设 | 批量操作原子性、冲突、引用闭包 |
| 编译与试跑 | 固定 revision | compile diagnostics / smoke run | 真正 compile/run；拒绝空模型或假成功 |
| 解释与改进 | evidence、brief 接受条件 | 结论和下一提案 | 数字可追溯；未测量项不得变成事实 |

### 5.2 避免“套模板”的约束

- 场景模板仅提供默认值、示例和候选组合。生成结果必须能增删实体、更换拓扑、改变数量与空间约束。
- 开始时确实是空模型；不先暗中加载固定六节点装配线再把名字改成仓库。
- 所有构件通过定义描述参数、连接规则、行为、lowering、视图映射。模型只引用定义，不把具体场景代码生成进宿主。
- 能力不支持时给出：缺失能力、受影响需求、可选近似、近似影响。需要用户选择重大近似时询问；没有答复不能悄悄简化。
- 修复循环默认最多 3 轮（可配置）。无改进或预算耗尽时保留草案和诊断，禁止无限试错或宣称“基本完成”。
- 将空间算术、路径搜索、容量限制、合法动作筛选放在代码中；LLM 提意图与结构方案，模型不负责凭语言保证几何正确。
- 接受来自额外插件的新范式：声明 validator/lowering/runtime/view 与组合边界。不能默认所有范式都能共享一个仿真时钟。

### 5.3 Agent 工具面：先少后扩

目标工具命名在 T01 固定，可按任务分组提供，不能每轮注入所有模型 JSON。

1. `project_open/create`、`capabilities_describe`：项目和可用能力。
2. `requirements_update`：记录需求与假设。
3. `model_query`：按对象、关系、子图、选择范围读取。
4. `model_propose`、`model_validate`、`model_commit`：局部变更与提交；UI 使用同一服务。
5. `experiment_create/start/status/compare`：固定版本的实验与证据。
6. `decision_inspect`：读取特定时刻的观测、候选和选择，不把内部推理链当证据。

模型生成通常通过上述工具组合。不要实现“generate_everything(prompt)”后把全部流程封在不可观察的函数里。

## 6. 人机共创协议与 DSH 接入

### 6.1 Host 与 Client

- Host 领域服务提供唯一写入口，客户端维护订阅投影。纯组件接收字段、回调和 DSH slot hooks。
- 正式通信优先用 DSH 支持的 Remote/Connection 契约。具体外部包如何生成严格 codecs 在 T01 做可运行验证；若需要少量 exact Fetch 文件/二进制路由，也通过 DSH 已认证 Connection 注册。
- 不改 DSH 私有全局对象、不依赖 DOM query 获得业务状态、不起 iframe 独立应用。
- 文件与工作区访问使用 DSH 能力边界；传入 artifactId，而非允许模型任意指定主机文件路径。
- 会话 A 与 B 可以绑定同一 artifact；切换会话不创建另一份模型副本；fork 会话不默认 fork 模型。

### 6.2 选择与上下文

`SelectionContext = project + artifact + revision + view + objectIds + optional run/replication/simTime`

- 用户点击、框选、时间轴定位生成上下文；同一 stable objectId 在两种视图中高亮。
- Agent 在请求构造时读取当前上下文快照，返回操作携带该 revision。用户之后改变选择不改变已发出操作的目标。
- 只把必要的参数、邻接关系、诊断和约束提供给 LLM，避免把整场景 mesh 或全部 trace 发给它。
- DSH 会话中保存足够的版本引用、变更摘要和结果引用以供复盘；领域持久化数据仍归 Artifact Graph。

### 6.3 提案、接受、撤销、冲突

- 局部命令至少包括：add/remove object、set typed parameter、connect/disconnect、set transform、edit navigation、bind policy、replace visual asset。
- 校验先于提交；一组变更全部成功或全部不生效。删除对象必须显式处理所有引用，不静默丢边。
- AI 提案可在视图中以幽灵位置、差异表或高亮呈现。普通拖动的预览是本地草稿，松手后提交一次事务，不能每帧写 revision。
- `baseRevision` 过期返回冲突。首版不自动覆盖也不盲目自动合并；显示受影响字段，让 Agent 重新读并重提。
- 撤销通过补偿事务产生新版本。撤销已运行模型的编辑，不删除旧 run/evidence。
- 接受/拒绝/撤销与版本冲突采用同一状态源；不可显示已接受但 Host 提交失败。
- proposal 状态机至少有 draft、validated、committed、rejected、superseded、failed，所有转换有可追溯原因。

## 7. 首个仓储／产线场景包

### 7.1 首轮支持范围

- 空间：矩形场地、静态货架与工位、二维地面导航图、显式通道宽度、占位三维几何。
- 实体：订单、搬运任务、货物、搬运车、拣选工位；人员工位先用可校准服务时间分布。
- 流程：订单到达、生成任务、领取任务、装载、运输、卸载、拣选、出库。
- 资源：有限车辆、有限工位、共享通道/路段的显式预约或容量。
- 策略：FIFO、加急优先、最近可用车；Jev 后续作为同一决策点的替换实现。
- 实验：固定时长或固定订单数后排空（两种明确区分）、热身期、独立重复、固定种子计划。
- 指标：完成量、吞吐、订单流动时间、等待时间、P95、车辆利用率、空驶距离、路段占用/冲突、超期比例；定义与分母必须明确。

不在首轮：真实车辆动力学、多楼层电梯、机械臂抓取、精细人群、真实 PLC 接入、自动构建摄影级资产。

### 7.2 初始回归基准（仅用于测试，不是用户默认事实）

基准 W1：30×20 m 场地，西入库、东出库，4 个货架区、2 个工位、2 辆车；网络边附长度与容量；普通/加急订单比例、到达分布、处理时间均由 fixture 明确给定。所有分布单位为秒。

必须变体：

- W2：20×12 m，1 辆车、3 个工位、L 形通道；不能使用 W1 对象 ID 或坐标常数才能工作。
- W3：封闭一条通道，部分任务不可达；明确诊断并阻止不合法派单。
- W4：高到达率压力场景；积压必须真实增加，不能因为动画限额而降低队列指标。
- W5：加急订单在普通任务处理中到达；默认任务不抢占，调度策略只作用于下一次分配。若支持抢占，另定义契约。

### 7.3 车辆和任务状态

车辆：idle → assigned → moving-empty → loading → moving-loaded → unloading → idle；异常进入 blocked/failed，恢复策略显式。

任务：created → queued → assigned → executing → completed；取消、失败各有终态与资源释放语义。

不变量：

1. 一个任务只被分配给一个有效执行者；请求重复不能生成重复任务。
2. 资源占用不超过容量；车辆不能同时执行两个排他的任务。
3. 没有连接路径的起终点不能直接直线穿过货架。
4. 路段预约在完成、取消、失败后释放；检测无进展/死锁，返回诊断。
5. 库存/订单/货物数量守恒；已经出库的实体不能仍在处理中。
6. 图、轨迹和指标读取实际运行事件；渲染限额只影响显示密度。

## 8. 决策、Jev 和其他模型如何参与

### 8.1 两种 AI 层次

- 建模助手：DSH LLM 理解目标、提出结构与参数假设、解释诊断、调用实验、修改模型。
- 被模拟对象的策略：车辆派单、人员判断、异常处置等，通过 decision provider 参与系统行为。

二者的输入、权限和时钟不同。不要把一次 Agent 对话当成被模拟人的行为时间。

### 8.2 第一个决策点：dispatch-next-task

触发：出现待处理任务且存在合格空闲车，或车辆释放资源。

观测包括：允许候选任务/车辆、任务优先级/截止时间、起终点、已计算的可达路径长度/预计时间、车辆载重/状态、当前队列、约束和调度目标。

候选动作：稳定 actionId 引用 `(taskId, vehicleId, routeId)`，加上明确定义的 wait/escalate。候选先由代码筛选；Jev 不发明任意任务/车辆 ID。

结果流程：provider 选择 → 依据请求状态版本重新检查合法性 → 原子占用资源 → 运行时应用动作 → 写决策记录。过期结果不能作用于已经变化的世界。

### 8.3 提供方与不确定性

- `rule.fifo`、`rule.nearest` 为无需 API 的确定性基线。
- `jev` 把 observation 转为 TypeSafe 的 typed questions；Choice 选候选，Score/Noul 仅用于各自清晰问题。不要通过聊天 completion 端点假装 Jev 接入。
- `specialist` 为后续任务训练的模型提供方，输入输出与同一决策点匹配。
- 输出没有置信度的提供方不伪造 confidence=1。不同提供方的原始分值不可直接比较。
- Jev 的判断概率不是现实人员行为频率。人因策略需有数据校准、适用范围与情景假设。
- 第一轮保留无 Jev 的完整闭环。真实 API 未取得访问时，记录接入未验证；不能用 mock 验收真实 Jev。
- 阈值通过本地验证集选择，记录 false decision/abstention/fallback；不要直接抄示例的 0.8 并宣称已校准。

### 8.4 时钟、延迟、重放

首版正式模式采用 **barrier 决策**：事件运行到决策点暂停推进，等待实际提供方结果，再以同一逻辑时刻应用。墙钟耗时独立记录，不伪造“零成本实时控制”。

- 按事件推进，不能受浏览器帧率控制。加速播放不增加决策次数。
- 暂停时的相同 simTime 事件采用稳定顺序；异步响应到达顺序不能决定最终派单顺序。
- 超时/取消：带 signal/deadline；采用配置的规则 fallback 或失败终止，并写明，不默默换模型。
- 录制模式保存请求、提供方版本、输出和实际动作；重放模式只读已记录决策，禁止重新调用远端。
- 新模型推理即使种子相同也不保证复现。严格实验固定 exogenous arrivals/service draws 和决策记录；新策略比较是新的 run。
- 实时 deadline 模式为后续扩展：需要显式决策生效时刻、过期拒绝和无决策时安全动作。未实现前不得暴露“实时控制”选项。
- 每个 run 设置 maxDecisionCalls、maxInputBytes、maxWallMs、并发上限；提供方可返回费用，没有实际费用数据时标记估计。

## 9. 仿真、空间与实验闭环

- 正式执行沿用 `ExecutionService → ExecutionTargetRegistry → supervised native provider → SimulationSession`。
- 原生当前不支持调度暂停或导航资源时，改 LogicPilot runtime/provider；不通过客户端悄悄补一套不同的执行算法。
- 每个 run 绑定模型、空间、策略、实验、运行时、插件配置的版本闭包。之后的模型编辑创建新版本；旧 run 仍可浏览。
- 状态与遥测包含 runId、replicationId、seq、simTime；重连检测 gap，重新获取基线，不把缺帧补成假运动。
- 轨迹播放允许插值展示，但不得改变指标和逻辑时间。仅有终态摘要的 provider 不得显示“真实实时轨迹”。
- completed、cancelled、failed 区分；取消不是 finish 排空事件。DSH 重启后在途任务未实现恢复则明确 interrupted/failed，不能仅因元数据存在就显示继续运行。
- checkpoint/fork 必须探测能力。没有原生 checkpoint 时提供“相同初始状态重跑”；不把它叫“从当前时刻分叉”。
- 多次重复采用独立随机流。策略对照复用外生输入样本或独立命名随机流，避免因一次额外采样使后续到达完全不同。
- 指标包含公式、统计窗口、分母、warmup 和 replications。单次 demo 不能给出通用“提升百分比”的结论。

## 10. 可视化和可替换资产

### 10.1 文档体验

- 一个逻辑模型文档，允许 DSH 在不同 pane 中显示它的 Flow/3D/Experiment/Decision 视图实例；它们不复制模型。
- 使用 DSH 当前主题 token、slot、tab registry、资源打开机制和 locale。重载/卸载清理 listener、GPU 资源和订阅。
- Flow 支持选择、拖动排版、连接、参数修改、诊断定位。3D 支持选择、移动/旋转、尺寸编辑、量尺和导航叠层。
- 视图同步 selection 和 run/time cursor。相机与缩放可保持每视图独立；改变相机不写业务版本。
- 几何/路径诊断直接标出冲突对象与位置；不能只在聊天里说“不合法”。
- 从运行时间轴点击决策，展示观测、候选、选定动作、置信度、fallback 与已应用结果。LLM 的自然语言解释必须引用这些记录，不能虚构内部思考。

### 10.2 占位 3D

- 领域构件提供参数化几何：设备、货架、工位、车辆、货物、区域；尺寸来自已记录参数。
- 模型生成时为缺失尺寸记录估计与依据；通道/边界检查使用代理几何，不依赖材质或 mesh 细节。
- 首版静态可视资产替换选择 GLB，导入后绑定 objectId + assetId；记录源文件 digest、单位、朝向、pivot 和视觉缩放。
- 原始 GLB 不得覆盖语义尺寸或碰撞代理；用户可另外显式修改并重新校验。GLB 导入作为单独后续任务，未通过验收时只提供占位形体。
- 不自动下载不明模型或让 AI 随意执行导入脚本。外部纹理/路径限制、资源大小限制与导入失败恢复写入资产测试。

## 11. 专用模型训练：第二阶段能力

首轮先记录数据和评价接口，不实现一个空训练按钮冒充完整链路。

推荐首个训练任务：根据工单结构化字段与文本特征预测处理时间，用真实完成记录或可信仿真标签验证。

```text
LLM 提出可解释特征问题
  → Jev/其他特征提供方提取结构化特征
  → 用有来源标签训练专用回归模型
  → 在冻结保留集评估
  → 包装为 prediction provider
  → 在固定仿真实验里比较系统指标
  → 误差分析反馈给 LLM，改进下一版特征或数据
```

- 训练、验证、测试按任务/时间/场景分组隔离；同一 episode 的相近样本不能随机泄漏到两边。
- 外层最终测试集冻结；提示词或特征迭代仅使用开发集。Jev 的响应不能自动被当成真实标签。
- 同时比较简单常数/规则、传统特征模型、Jev 特征模型，记录特征提取成本与推理成本。
- 新权重作为有版本 artifact 发布，实验显式选择；训练完成不自动替换正在运行的 provider。
- 在仿真数据上学到的策略只证明该仿真假设下表现；现实部署前另做验证。

## 13. 验收场景与证据

### A. 从空项目生成（首要验收）

输入自然语言，不加载现成工程文件。生成 brief、假设、模型、空间和实验。至少验证三种不同输入结构，而非同模板换名称：串联产线、搬运仓储、另一领域如维修服务站。

自动检查：用户给定对象数量/场地边界/容量与输出一致；单位正确；不支持项显式拒绝；模型可编译、可执行；最终报告引用真实 run。判断自然语言任务是否满足要求使用人工可读 rubric，不只看 JSON 合法。

### B. 人机共同修改

人选择或移动工位；AI 对同一工位提出局部改动；用户接受/修正/撤销；2D/3D/参数与版本一致。双会话同时编辑触发冲突，不丢数据。运行中编辑不会改变旧 run。

### C. 搬运执行

手算一条路的距离/速度/装卸时间与模拟完成时间一致；两车争用容量 1 路段不同时占用；封路后重算合法路线或报告不可达；取消后资源释放。

### D. 决策实验

相同外生输入，FIFO 与最近可用策略各跑至少 5 个独立种子；输出指标定义与每次结果。Jev 请求带合法候选和版本；失败/fallback 可见；决策重放零远端调用。不能预设性能必须改善。

### E. 运行与安装

新 profile 安装只选择支持版本；浏览器真开 DSH 面板、模型编辑、原生运行、重连、刷新、退出重启；Windows 子进程无残留；缺 API key 不阻塞规则基线。安装包不依赖源码绝对路径。

### F. 跨场景泛化

接入维修服务站领域包：对象变为服务请求、技术员、维修工位、备件区。项目/事务/执行/决策接口不增加 `if repair` 分支。允许新增领域构件和规则，但不能复制宿主服务。

## 14. 推荐测试预算与运行限制

以下是初始验收配置，不是永久产品上限：

- M1：20 个语义对象、100 个实体的确定性手算与基本运行。
- M2：30×20 m、2–4 辆车、最多 500 个任务；测试 1,000 个对象的空间校验耗时并记录，不承诺未经测量的 FPS。
- 单批原生推进限制事件数/墙钟片长，取消响应目标 2 秒内；超时必须有证据，不能无限等。
- 浏览器运动采样与业务事件分离；大 trace 分页/索引，不每秒重传完整运行。
- 真实 Jev 最初 maxDecisionCalls=20、并发≤2、每调用超时由官方 SDK 支持值配置，总测试额度在实施时明确；不足时完成本地链路并报告外部验证状态。
- LLM 生成修复最多 3 轮，工具重试有界，编译错误原样保存。不得用“继续”自动续接绕过实验预算。

## 15. 何时才允许改 DSH 源码

默认零修改。遇到缺口先查公共服务/slot/Remote/插件生命周期，再写最小可运行复现。

可以提出上游补丁的例子：外部插件无法通过公开机制声明所需 Remote codec；一个必要的文档操作缺少可贡献 slot；身份敏感依赖冲突不能在安装阶段诊断。

不属于 DSH 改动理由：模型参数复杂、原生内核缺导航/调度暂停、需要实验数据库、需要训练脚本、想沿用旧 IDE 的全局 store。

每个拟改动必须记录：需求、已试插件路径、最小复现、最小公共接口变化、版本影响、能否 upstream。未经证据不得 fork 后重写主循环。

## 16. 交付证据和停止条件

每个任务写一条日期化记录：任务号、修改文件、真实命令、退出码、关键结果、浏览器验证、未完成项。实现与验收状态分别填写。

必须停下当前依赖任务并报告具体阻塞的情况：

- 用户文件存在无法安全合并的同位置修改；无法确认某个凭据/费用/外部数据用途；所需原生能力没有实现却被下游要求。
- 未知版本不匹配、核心插件解析到两个身份不同实例、运行结果不能对应模型 revision。
- 生成循环到预算上限、场景依赖尚不存在的能力、空间要求相互矛盾。

停止该依赖任务不意味着放弃所有工作：可继续独立本地测试、生成诊断或准备待验收结果。不得把外部 API 未验证记录为通过。

## 18. 固定验收输入：交给实现者的具体题目

下列文字是验收数据，不是当前用户要求立即创建的真实工程。T04/T12 实现时保存为 fixtures，记录实际生成过程。不要把预期模型 JSON 暗中传入 LLM。

### G01 — 空项目的最小生产线（M1）

> 建一个小装配线：每 10 秒固定来一件，先排队，再由一个工位处理 6 秒，随后离开。先做 30 件，不需要空间运输。我要看等待和完成时间。

预期：四类语义 source/queue/service/sink；参数与单位正确；运行依照明确的首件到达约定；无资源竞争时等待为 0。若首件在 t=10，到 t=306 完成 30 件；若契约采用首件 t=0，须明确声明并以 t=296 验证，不能混用。

### G02 — 仓储搬运（M2）

> 一个 30×20 米仓库，左侧一个入库口、右侧一个出库口、中间四组货架，两辆搬运车服务两个拣选工位。车辆 1 米/秒，装货和卸货各 5 秒，拣选每单固定 20 秒。先按每 30 秒一单跑一小时，看瓶颈在哪。

预期：指定数量精确遵循；架尺寸和导航布局若未给则作为假设；运输时间来自路径距离/速度；一小时是到达截止还是硬终止必须明确，默认先给可解释的实验草案；不能用一条服务节点近似全部搬运而不说明。

### G03 — 结构变化而不是改参数（M2/M4）

> 在空项目里建 20×12 米的小仓库，一辆车服务三个工位，通道必须是 L 形，不能穿过货架。入库和出库在同一侧。订单完成后货物先去暂存区，再出库。

预期：相较 G02，实体数量、起终点位置、空间拓扑和业务流程均发生变化；能构建并运行；不是复制 G02 再改标题。

### G04 — 选择驱动的局部共创（M1/M2）

先由测试操作者选中拣选工位 B，再输入：

> 把这个工位移到出口附近，保留两米通道。其他设备和参数先不动，给我看修改，再比较搬运距离。

预期：proposal 目标为 B 的 stable ID；未改变其他设备/参数；通道校验有具体结果；旧实验保留；新实验和旧实验对应不同空间版本。位置不合法时显示诊断，不提交。

### G05 — 参数和策略对照（M3）

> 普通和加急订单按 8:2 到达，已经开始的任务不抢占。先比较 FIFO 与加急优先，再比较 Jev 派单。保持订单样本一致，报告每类订单的延误、总吞吐和调用成本，不要只挑最好的一次。

预期：非抢占约束成立；使用明确外生样本集；分组指标和每次重复结果齐全；Jev 缺凭据时规则对照可完成且 Jev 显示未运行；不预设 Jev 必胜。

### G06 — 跨领域（M4）

> 从零建一个维修服务站：客户把设备交到接收台，两位技术员共用一个检测台，维修后到取件区。有些任务需要从备件区取件。我想比较增加一位技术员还是增加一个检测台更有效。

预期：先查询维修领域包及共享资源能力；缺失的分支比例、服务时间记录为假设或提问；模型里是请求、技术员、检测台和备件流，不能只把“车辆”改名为技术员。若缺备件取用能力须明确分阶段交付，不伪装已支持。

### G07 — 不支持能力（能力诊断）

> 在两层仓库里加电梯运输，再让机械臂通过摄像头识别散乱物品并抓取，给出准确的实际成功率。

预期：逐项报告能力与证据缺口；不生成虚假电梯/视觉/接触动力学并宣称可执行；不把模拟成功率叫现实成功率。能保存需求和候选扩展方案。

### G08 — 矛盾空间要求（几何诊断）

> 宽 5 米的房间里沿宽度并排放两个各宽 2 米的设备，中间留 2 米净通道，不能重叠、缩小或越界。

预期：指出至少需要 6 米，总宽约束冲突；保留用户参数；建议可选改动，不偷偷缩小设备或忽略通道。

### 18.1 手算和不变量基准

H01：任务 t=0 已就绪，车辆在装载点，单程路径 10 m、速度 1 m/s、装载 2 s、卸载 3 s，无其他竞争。任务完成 t=15；如需返回起点，车辆回到起点 t=25。订单完成时间与车辆再次可用位置不能混为一个指标。

H02：将 Flow 节点从屏幕左侧拖到右侧，H01 运距仍为 10 m。将物理终点改为沿合法路径 15 m，任务完成变为 t=20，返回起点 t=35。

H03：两辆车从一条容量为 1 的路段两端同时请求通过；稳定仲裁后任意时刻占用数≤1，另一辆有可追溯等待。取消获胜者后资源释放，等待者可继续或得到明确取消语义。

H04：同一 `model_commit` 幂等键提交两次只有一个新 revision；同一 run start 请求两次只有一个 run；网络重连不能重复执行已完成决策。

H05：相同模型、初始状态、外生随机流和已记录决策重放，事件顺序/指标匹配，远端 API 请求计数为 0。只匹配动画外观不算通过。

### 18.2 评分与发布判定

每个生成案例分别记录：需求遵循、假设透明、语义校验、空间校验、真实运行、可共创、证据追溯，各项 0=失败、1=有明确限制、2=完整满足。

总分仅帮助比较，不能掩盖硬失败。虚构运行结果、覆盖用户给定约束、非法资源占用、版本不一致任一项发生，都不能发布为通过。

所有正向案例必须真实执行可支持部分；负向案例以正确拒绝/解释为通过。真实模型生成具有波动，至少保留多次独立尝试和失败记录，不删除失败运行来提高通过率。
