# AI 面板 UX 对照与改进清单

> 状态:**评审完成,进入实施**(2026-08-24)
> 生成日期:2026-08-24
> 目的:把 AI 面板(Copilot)的现有交互逻辑与市场主流 in-IDE 助手的标准行为逐条对照,由人工逐条拍板后再做成 `slice` 实施。**本文档只做盘点,当前未改动任何代码。**
> 评审方式:对每条在"建议"列标注 \*\*接受 / 调整 / 不做\*\*;未标注的条目默认不实施。

**评审结论(用户拍板)**

- §3 未标注的条目全部按"建议"列实施(D1 除外,D1 选 Claude Code 式:保留权限三档,Ask/Plan 并入对话表达)。
- §4 证据型结果:不保存在聊天 UI 里写死;方向为做成 **AI 技能/插件**——该呈现时由 AI 主动调用呈现能力(类似 AI 画 mermaid),这是下一步的架构项(S8),先出设计文档。
- 实施顺序(每条独立 slice + 全量门禁截图确认):S1 =D1+D2 → S2 =G1 → S3 =A1 → S4 =B1+B2+C1 → S5 =E1 → S6 =F1 → S7 =A2 → S8 =证据结果技能化(架构设计先行)。


## 1\. 参照系(标准从哪来)

|参照|对应场景|取值来源|
|-|-|-|
|GitHub Copilot Chat / Cursor|面板型助手:输入区、流式消息、消息内操作、模型切换|公开 UI 行为,实施时用 browser-use 截图对比确认|
|Claude Code / Codex CLI|代理型转弯:权限三档、工具调用确认、中断/恢复|公开 CLI 交互行为|
|ChatGPT / Claude 客户端|会话管理:New chat、重命名、归档、搜索|公开 UI 行为|

约定:凡是与某条标准不一致的,不直接改;本文档将它列出来,你确认后才进实施清单(见 §5)。

## 2\. 现状总览(改前基线)

面板当前包含:会话列表(自动创建、归档、置顶)、会话内消息流(用户/助手气泡、步骤跟踪、结果徽章)、Assistant 流式工作卡 + 实时输出、模型/工具配置(`Configure`)、模式选择(Agent/Ask/Plan)、权限选择(Full access/Workspace/Read only)、`@`/`/` 上下文与命令注入、`/clear` `/build` `/optimize` `/sweep` `/explain` 命令、语音输入、检查点 Resume/Discard 卡片、独立"结果区"(build/run/optimize/explain 的证据表与图表)。

## 3\. 差异清单(建议调整项)

### A. 会话管理

|#|现状|标准行为|建议|风险|优先级|
|-|-|-|-|-|-|
|A1|没有显式 "New chat" 按钮;发消息才隐式创建会话,列表页只是历史|列表页有显式「新建对话」入口|在 Sessions 列表顶部加 `+ New` 按钮(进入空对话态)|低:纯入口补充|P1|
|A2|会话标题 = 首条请求原文,无法重命名;无搜索|自动命名 + 可重命名 + 可搜索|行内更多菜单:重命名/归档/删除;搜索按收益后置|中:涉及会话 store 字段与持久化|P2|
|A3|会话随"未配置模型"发送也会创建(上一轮改动)|无矛盾|**保持现状**(用户要求的行为,列入§4)|—|—|

### B. 消息与流式

|#|现状|标准行为|建议|风险|优先级|
|-|-|-|-|-|-|
|B1|生成中不落消息,而是显示"工作卡"(步骤 + 实时文本);完成后整条 append|发送后立即生成一条流式助手气泡,边生成边追加|改为"流式气泡":发送即创建助手消息,onToken 直接更新该消息,失败时该气泡转错误态|中:改动 `sendAssistant` 的 append 时机与 conversation store 的更新接口|P1|
|B2|完成后消息固定,内有步骤跟踪/结果徽章/操作|同上(结果并入消息)|步骤与徽章保留在流式气泡内|低|P1|
|B3|`ai-composer-status` 有本地运行点 + 权限下拉|—|保持(领域需要)|—|—|

### C. 结果渲染(双轨结构)

|#|现状|标准行为|建议|风险|优先级|
|-|-|-|-|-|-|
|C1|build/optimize/sweep/explain 结果独立渲染在消息流下方的"结果区",与对话不同步滚动、切会话后残留|结果属于消息的一部分,伴随消息滚动与清理|结果卡片作为助手消息的子内容(与 B1 一起做)|中:重构结果区到消息模型|P1|
|C2|结果证据(诊断列表、DES 块统计、图表、DSL/Run log 折叠)、破坏性操作审批卡片|无对应标准|**保留**(建模域特色,见 §4)|—|—|

### D. 模式与权限选择器(双选择器)

|#|现状|标准行为|建议|风险|优先级|
|-|-|-|-|-|-|
|D1|输入行有 Agent/Ask/Plan;底部还有 Full access/Workspace/Read only,两套语义重叠|Copilot Chat:模型决定工具,权限单一档;Claude Code:仅权限三档|二选一:保留权限三档(Claude Code 式),Ask/Plan 合并进 Agent 对话自然表达(用提示语说明"只分析/先出计划");或保留模式三档、权限只留 2 档|中:两种方案影响工具装配与审批逻辑,需选型|P1  选claude code式|
|D2|模式切换后无明确视觉层级,Plan 状态仅在底部小字|模式状态通常显示在输入行或头部|随 D1 选型同步调整|低|P2|

### E. 模型选择

|#|现状|标准行为|建议|风险|优先级|
|-|-|-|-|-|-|
|E1|模型下拉只有 "Auto" + "打开设置"|直接列出可用模型(分组:最近/收藏/全部)|接入已有 `/api/ai-providers/models`,下拉直接选模型|中:UI 与 provider 侧模型发现已有基础|P1|
|E2|未配置时显示 `Not configured`|—|保持(与错误态配套)|—|—|

### F. 工具控制

|#|现状|标准行为|建议|风险|优先级|

|F2|`@model` `@selection` 注入 + 块数徽章(pill)|Copilot Chat 的 `@` mention 同构|**保持**(已接近标准)|—|—|

### G. 文案语言一致性

|#|现状|标准行为|建议|风险|优先级|
|-|-|-|-|-|-|
|G1|英文模式标签(Agent/Ask/Plan/Full access/Read only/Workspace/Plan mode/Not configured/Local)+ 中文错误文案混杂|界面语言一致(产品的界面语言应统一)|确定界面语言(建议中文),统一所有标签与提示|低(纯文案,先改文案后与 D1 配合)|P1|

### H. 已对齐/接近标准(无需改)

* Enter 发送 / Shift+Enter 换行 / 组合输入时(IMM)不误发;空输入时 Send 禁用;busy 时自动变成 Stop 按钮。
* 消息操作:Retry、Copy、Undo(带 diff 回看)、View changes。
* 工具审批卡片(Keep current model / Apply and continue;Deny / Allow)。
* 检查点卡片(Resume / Discard)对应 Claude Code 的中断-继续语义。
* 错误态对话内呈现 + 重试(上一轮已按你的要求改好)。

## 4\. 特色保留(与标准不同但建议保留,逐一确认)

|项|理由|
|-|-|
|错误 turn(未配置模型时仍进入会话)|你上一轮明确要求的行为|
|确定性命令(`/build` `/optimize` `/sweep` `/explain` + 提示词建议)|无模型时也能工作的领域路径;与面板级 quick actions 并存|
|证据型结果(块统计/CI/证据链/轨迹图)|建模验证是产品核心价值,不是聊天 UI 装饰  但是这个应该作为内置的ai技能、插件一类的，而不是写死在聊天中；也就是说，该呈现的时候，要ai有能力主动呈现给用户，就类似于ai可以画mermaid图一样|
|破坏性操作用于确认|防误改模型,安全约束|
|本地运行点/权限指示|用户需要感知在执行环境|
|语音输入|非主流但明确可用的功能;若 WebView 不支持会给出错误提示;可作为设置项保留(默认关)|

## 5\. 实施工作流(评审通过后)

1. 你在 §3 每条标注 **接受 / 调整 / 不做**,§4 标注 **保留 / 砍掉**。
2. 按优先级排序成实施清单,每条独立 `slice`:
改动 → 全量门禁(`windows-build.ps1 -Test` / vitest / typecheck / build / Playwright 验证)→ 截图(含桌面端)→ 你体验确认 → 提交。
3. 需要确认标准行为细节时,用 browser-use 打开 Copilot/Cursor/ChatGPT 对应界面截图对比,截图作为实施证据进提交说明。
4. 明确不做的:不因"与标准不同"而删掉建模域特性;不一次性大改 3 个以上条目。
