# 交给后续模型的执行提示词

以下正文可直接复制给接手模型。它只授权执行用户指定的实施任务，不授权无限扩大范围。

---

你在 Windows 仓库 `C:\Users\JasonJin06\Desktop\LogicPilot` 中实现 LogicPilot 的 DSH 插件路线。

先完整阅读：

1. 根 `AGENTS.md`。
2. `docs/architecture/dsh-modeling-cocreation-plan.md`。
3. `docs/maintenance/dsh-coCreation-tasks.md`。
4. 当前任务依赖的日期化验收记录，以及相关文件当前源码。

然后检查 `git status --short`。工作树包含用户和其他开发者未提交改动；不得 reset、checkout 恢复、覆盖或全量暂存。

本轮执行任务：【填入 T00～T15 中的一个任务号；未指定则从第一个依赖已验收且尚未完成的任务开始】。

产品目标：DSH 是宿主；LogicPilot 的项目模型、共创命令、仿真、决策、实验和视图作为插件深度接入。用户从空项目说“我要一个什么样的系统”，LLM 帮助生成可校验模型，人通过流程图和 3D 与 AI 共同修改，再通过真实实验改进。小型仓储搬运只是第一个领域，不得硬编码成唯一场景。

必须遵守：

- 默认不改 DSH 源码。使用 Cordis 服务、DSH 工具/上下文、Connection/Remote、slot/tab 和生命周期。
- 不再扩展 `integrations/dsh-des` 为正式独立应用；它只是原型参考。不要从它的小型 JS 模拟器推出正式运行结果。
- 复用 Artifact Graph、ModelPatch、ExecutionService 和 native provider。框架 peer 由 DSH 提供，不把旧 DSH 包装进 profile。
- 项目拥有模型；会话引用模型。UI 与 AI 修改同一模型、同一 revision、同一事务入口。
- 先完成用户行为，再做必要抽象。不要创建大量空接口/registry 或只搬文件就报告解耦。
- 从空项目生成不是套固定六节点模板。显式保存假设，调用已安装能力，真实编译与运行；不支持项如实报告。
- 不确定的 SDK/API 查当前官方文档或本机实际声明，不猜名字和签名。
- 外部 API 未调用的部分不能记为通过；mock 不等于真实模型，重跑不等于 checkpoint 分叉，动画不等于执行 trace。
- 每次只做本任务范围内的必要更改，运行对应验证。失败就修，不能用跳过测试、扩大容错或假数据掩盖。
- C++ 构建通过 `./scripts/windows-build.ps1 -Preset windows-msvc-dev -Test`，CMake 变化加 `-Configure`。
- 保护 API keys，不打印配置中的凭据、不把秘密发给模型、不覆盖用户安装的其他插件。

任务结束前：

1. 实际执行执行单要求的功能和验证。
2. 写日期化交接记录，区分实现、测试、真实调用、未验证和阻塞。
3. 更新任务状态表中的实现与验收两列，并链接证据。
4. 最终回复说明可用行为、验证证据和具体限制，给出下一任务。禁止没有证据的“全完成”。

若发现需修改 DSH 核心：先写最小复现和已尝试插件接入方式，说明缺失的公共扩展点；不要直接 fork 重写。

## 给用户的执行建议

第一次交给实现模型时指定 **T00**，验收后再执行 **T01**。不要一次发送“把整份计划全部实现”给容易偏离范围的模型。

M1（T00～T05）结束时应能亲自体验：空项目→自然语言建模→人修改→原生仿真→保存与恢复。若仍只能看到固定演示图，拒绝将 M1 标为完成。

随后按 M2 仓储、M3 决策实验、M4 泛化交付推进。训练与 GLB 资产替换属于 M5，不应阻塞前面的人机共创闭环。
