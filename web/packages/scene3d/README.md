# @logicpilot/scene3d

3D 场景视图的**渲染器无关**内核。相机数学、文档→场景投影、3D 布局与仿真运动归约都在这里，全部是纯函数或纯状态对象，因此可以在 Node 里穷尽测试，不需要 WebGL。

Three.js 图层住在 `web/apps/ide/src/scene3d/`，只做"把这里算好的值翻译成引擎对象"。

## 为什么单独成包

沿用仓库既有分层（`@logicpilot/canvas` 纯几何 + `ModelCanvas` 在 app 里画 SVG）：

- 纯逻辑可在 Node 里测，覆盖边界与失败路径，不需要浏览器
- Three.js（约 150KB）不会因为要测相机数学而被拖进依赖图
- 将来若要做独立查看器或 worker 侧布局，这一层可以直接搬

## 坐标约定

**这些约定是决定，不是巧合。改它们会同时改坏视图和测试。**

世界是 **Y 轴向上**。模型文档的坐标映射：

```
world.x = model.x * LAYOUT_SCALE      // LAYOUT_SCALE = 1/50，模型像素 → 世界单位
world.z = model.y * LAYOUT_SCALE      // 模型的"下"变成远离相机的方向
world.y = containerDepth * LEVEL_HEIGHT   // 容器嵌套层数 → 高度
```

| 量                               | 值        | 位置          |
| -------------------------------- | --------- | ------------- |
| `MODEL_UNITS_PER_WORLD_UNIT`     | 50        | `layout3d.ts` |
| `LEVEL_HEIGHT`                   | 5         | `layout3d.ts` |
| `NODE_FOOTPRINT` / `NODE_HEIGHT` | 3.2 / 1.4 | `layout3d.ts` |

要点：

- **模型 y 映射到 world z，不是 world y。** 保留 2D 画布的阅读方向；把两个模型轴映射到同一个世界轴会让平面排布退化成一条线（有测试固定这一点）。
- **嵌套用高度表达。** 这是 2D 画布无法表达的那一维，也是 3D 视图存在的理由。
- **`containerDepth` 对畸形输入必须终止**：缺失父节点按 0 层处理，`containerId` 成环时在 `MAX_CONTAINER_DEPTH` 停下，不会挂死渲染器。

相机（`camera3d.ts`）另有一套约定：

- `azimuth` 绕 +Y 旋转，0 表示相机在 +Z 侧、看向 -Z；角度归一化到 `[-PI, PI)`，长时间拖拽不会累积到失去精度
- `elevation` 是相对 XZ 平面的仰角，被夹在远离两极处——正好 ±90° 时前向量与世界 up 平行，基向量退化
- `fov` 是**垂直**视场角；水平视场由视口宽高比推出
- `panTarget` 的语义是"抓住画面拖动"：**目标深度上**的世界点在平移前后停留在同一屏幕像素。更近或更远的点会因视差偏移，那是正确的透视行为，不是误差。

**不能复用 `@logicpilot/canvas` 的 `Camera`。** 那个是 `{scale, panX, panY}` 的 2D 平移缩放相机，被 `ModelCanvas` 与 `SysMLCanvas` 消费；把它撑大以承载旋转与透视，要么破坏那两个调用点，要么留下一个一半字段对一半使用者无意义的类型。3D 需要位置与朝向，2D 的 scale+pan 模型根本表达不了。

## 空间图层：声明了 `node`/`path` 的模型

上面那套坐标约定只适用于**结构投影**：把 2D 画布的排布抬起来。对于声明了空间标记的模型，那是错的输入——画布 x/y 是编辑器自己发明的排布，把它挤出厚度得到的就是一张有厚度的流程图。

DSL 里有真正的空间语义，而且内核已经按几何在读它（`methods/process/process_flow.cpp` 的 `build_spatial_graph`：节点坐标、按欧氏距离加权、Floyd–Warshall 全对最短路，供 `moveTo` 花 `distance / speed`）：

```
node Dock { x = 0  y = 0  z = 0 }         一处地方，用模型自己的单位
path Run1 { node1 = Dock  node2 = Depot } 一条直线段，权重是欧氏距离
moveTo Ship { node = Bay  speed = 10 }    沿路网行进
```

`spatialGraphFromDocument` 是这套读法的前端，`buildSpatialScene` 把它画成**两层**：

| 图层     | 内容                                                     | 位置来源                   |
| -------- | -------------------------------------------------------- | -------------------------- |
| **地面** | 每个 `node` 一个标记，每条 `path` 一条按真实长度旋转的带 | 模型自己的坐标，1:1        |
| **轨**   | 所有非空间标记的块（`source`/`sink`/`moveTo`/…）         | 文档顺序等距，摆在板前     |
| **桥**   | `moveTo { node = X }` → 地面上那个节点的一条线           | 两端都是上面两层的真实位置 |

桥单独成层、不受 "Links" 开关影响：目的地不是流向连接，把它折进 `links` 会让 "Links" 变成两个意思。

### 什么是真的，什么是惯例

这个区分在看图时很重要，所以写在这里而不只写在代码注释：

- **真的**：每个标记的位置、每条路径的长度，都用模型单位，1:1 映射到世界单位。板以世界原点居中（世界是观看坐标系），所以**相对**位置精确，绝对坐标不保留。
- **惯例**：标记直径与路径宽度。DSL 只声明"节点在哪"，从不声明"节点多大"，所以尺寸没有可画的事实依据；取板较短边的固定比例（6% / 2%），让用毫米写的模型和用米写的一样可读。状态栏用 `title` 明说这一点，不暗示模型声明过尺寸。
- **不摆放**：`z`。内核的空间模型是二维的（`NodePos` 只有 `{x, y}`），所以视图把路网画平，并通过 `usesZ` 上报，由面板说明。画一个仿真里不存在的高度是更好看的谎。

### 默认值与内核一致，而不是与方便一致

- 没有 `x`/`y` 的节点落在原点，因为内核读的是 `node_float_param(child, "x", 0.0)`
- 引用了不存在节点的 `path` 被丢弃，因为内核跳过它索引不到的边
- 重名节点取**后**声明，因为内核写的是 `positions[name] = ...`；视图若取第一个，同一次行程会算出和仿真不同的路径

被丢弃的声明进 `issues` 并计到 `issueCount`，面板把它显示出来——一个无声消失的 `path` 看起来像渲染 bug。

### 网格是一把尺子

地面下的单位网格让比例可以被**数**出来，而不只是被信任。格边长走 1-2-5 阶梯（`chooseGridCell`）：板太大时增大格边长而不是线数，所以每格始终是整数个单位，状态栏能直接报出 `grid 1`。

## 模块

| 文件              | 职责                                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| `math3d.ts`       | `Vec3`/`Bounds3` 与基础运算。刻意不用 three 的向量类型                                         |
| `camera3d.ts`     | 轨道相机：`orbit` / `dolly` / `panTarget` / `fitBounds` / `projectToScreen` / `isUsableCamera` |
| `layout3d.ts`     | 模型坐标 → 世界坐标，容器嵌套 → 高度                                                           |
| `sceneModel.ts`   | `SceneDescription` 等类型、kind → 形状/配色表、结构投影 `buildStructureScene`                  |
| `spatialGraph.ts` | `ModelDocument` → 声明出来的路网（节点/路径/锚点/不可用声明）                                  |
| `spatialScene.ts` | 空间投影 `buildSpatialScene`，以及两选一的分发 `buildScene`                                    |
| `motion.ts`       | 遥测 → agent 位置与插值：`flowAnchorsFromScene` / `placeAgents` / `AgentMotion`                |

`buildScene` 是面板唯一需要调用的入口：它问投影该用哪种读法，而不是让面板自己判断什么叫"空间模型"。

## 两个刻意的设计

**投影不含选中状态。** 选中是视图状态而非内容；把它折进 `SceneDescription` 会让每次点击都重建全部几何。渲染器按 id 应用选中材质。

**未知 kind 是一等结果。** `BlockKind` 是开放字符串，DSL 能引入调色板里没有的类型，模型也可能引用未安装插件的 kind。`KIND_VISUALS` 是"视觉兴趣表"而非完整注册表：表里没有的 kind 得到通用方块 + `knownKind: false`，界面会把它显示出来，而不是假装认识。

## 遥测映射

wire 帧把 agent 描述成**标量队列槽位**（`posX`，0 = 在服务台），不是坐标。这个映射只在此处定义一次：

- 流向轴从**服务块**指向**队列块**，所以槽位 0 在服务台，槽位越大越往队尾
- 等待中的 agent 落在轴上 `slot * AGENT_SPACING` 处，并被 `AGENT_MAX_QUEUE_SPAN` 截断——200 人的队列不该把场景拉到天边
- 在服务的 agent 落在服务块上，按 `Counters.servers` 声明的服务台数**垂直于轴**展开
- **只有模型同时有队列块和服务块时才画 agent。** 缺任一个就没有流向轴，硬画等于把它们放在没有意义的位置。（`flowAnchorsFromScene` 返回 null，图层关闭，界面说明原因。）

插值由 `AgentMotion` 负责：指数逼近，按**经过的秒数**而非每帧常数推进，因此 30fps 与 144fps 得到同样的运动，也能用固定 dt 测试。delta 被夹到 0.1 秒，标签页卡住 30 秒不会变成一次瞬移。

## 测试

```bash
pnpm --filter @logicpilot/scene3d test
```

108 项，覆盖：

- 相机不变量（绕轨道保持距离、仰角夹紧、方位角有界、`projectToScreen` 对相机背后的点返回 null 而不是镜像）
- `fitBounds` 把包围盒的八个角全部框进视口；退化内容（单个节点）仍给出可用距离
- **平移的抓取不变量**：目标深度上的世界点在平移前后停在同屏幕像素
- 投影覆盖、悬挂边被丢弃、未知 kind 兜底、确定性、空文档
- 布局轴映射不退化、容器链深度、循环与自引用容器终止
- agent 摆放（槽位顺序、服务台展开、队列截断、负/NaN 槽位）与插值（帧率无关、离开即移除、大 delta 夹紧、重置即吸附）
- **路网提取**：坐标缺省与不可读值的回退、路径按欧氏长度加权、对角线、重名取后者、悬空引用/自环/半条路径被丢弃并记录原因、`z` 上报
- **空间投影**：真实坐标与真实长度（含 100 倍单位的等比例对照）、标记尺寸统一且随板缩放、路径旋转角、重合节点不画带但保留声明、轨不与板重叠且按文档顺序等距、桥的两个端点、包围盒覆盖地面与轨、`buildScene` 的两条分支互不污染
- **网格尺子**：格边长走 1-2-5、退化与非法 extent 不产生 NaN

另有 `web/apps/ide/src/scene3d/spatialScene.test.ts`（8 项）用仓库真实的 `examples/move_route.lp` 走完整链路——真解析器 → 投影——以钉住单元 fixture 覆盖不到的那一段交接（参数名、坐标存储形式），并用 `examples/mm1.lp` 作反向对照（无空间标记的模型必须与结构投影逐字段相同）。

## 已知边界

- 兼容的画布类型只有 `graph2d/scene2d/flow/statechart/timeline` 语义；`scene3d` 目前渲染的是**结构 + agent**，以及**声明了空间标记时的地面**，还没有时间线与专用标注。
- 连线是块中心的直连。避障路由是另一个问题，做得草率会比一条明确的直线更差。
- agent 图层只认队列/服务这一对锚点。其他范式（状态机、系统动力学）的实时可视化需要各自的映射，目前没有。
- **空间图层上目前没有 agent 在动，而且这不是渲染层的缺口**：`stream_flow_replication` 只为流程模型发每块的计数器，不发 agent 位置（`server.cpp` 的分派注释写明 "Process flows stream per slice with per-block counters"），而 `pos_x` 在那条唯一的 agent 路径上还是队列槽索引。让 agent 沿路网跑起来需要内核记住行程轨迹（现在实体位置只在 `complete()` 时写一次）并让协议发出真实坐标——那是另一层改动，不在本层范围内。
- 空间模型的 `path` 之间不做避让：两条平行声明的路径会重叠绘制。内核取它们距离的最小值，视图把它们各自画出来，这是有意的——模型声明了两条，就画两条。
